# v0.9.5 implementation decisions

This log records decisions made autonomously while implementing v0.9.5. It is
not a roadmap and does not authorize work beyond v0.9.5.

## Capability evidence

- Provider model metadata is authoritative when it exposes a capability.
- Ollama Local capabilities come from `/api/show`; advertised `tools` remains
  distinct from behavioral tool-protocol conformance.
- Where a provider model-list response omits a capability, an explicit
  provider-adapter compatibility table based on official provider
  documentation may supply it. Unknown Cerebras capabilities remain disabled.
- Groq provider-native web search is limited to the officially documented
  `groq/compound` and `groq/compound-mini` systems.
- Google Search grounding is enabled only for the documented Gemini families
  or explicit provider metadata.

## Web search

- Web search is off by default and enabled explicitly per conversation.
- Ollama Web Search is a separate, application-mediated read-only integration
  with its own DPAPI-protected key. It does not list or select Ollama Cloud
  models.
- Application-mediated results are bounded to 5 entries, use only HTTPS URLs,
  are labelled untrusted, and are injected as data rather than instructions.
- Search performs no authenticated browsing, form submission, download,
  browser automation, or arbitrary page fetch.

## Images and persistence

- A turn accepts at most 4 images, 10 MiB per image and 20 MiB in total.
- Accepted types are JPEG, PNG, WebP, and GIF after signature sniffing. SVG and
  mismatched or executable payloads are rejected.
- Decoded dimensions are bounded to 16,384 by 16,384 pixels when the format
  exposes dimensions in a bounded header.
- Conversation history persists attachment metadata and a
  `missing-attachment` marker only. Image bytes are never persisted in v0.9.5.
- Cloud-image approval is remembered only in process memory for the current
  browser session and provider, and is cleared on conversation or workspace
  reset. It is separate from local-tool approval policy.

## Fallback and errors

- A request with images may use a configured fallback only when that fallback
  is vision-capable and any cloud-image privacy approval is valid.
- Images are never stripped to make a text-only primary or fallback succeed.
- Unsupported web/vision, invalid images, approval requirements, invalid
  citations, and unknown capabilities use typed capability errors and do not
  trigger the generic transient cloud fallback path.

## Real-provider validation

- The real v0.9.4 tool-protocol benchmark used only the authorized local
  `qwen3:1.7b` and `qwen3-coder:30b` models. The coder passed; the resident
  returned no valid native tool call and was not retried identically.
- No real cloud provider, Ollama Web Search, or cloud image upload is used
  without a separately applicable authorization.
- The v0.9.5 release gate therefore uses the production browser/API path with
  deterministic HTTP-boundary fakes. Real vision, cloud search, cloud image
  upload, and Ollama Web Search validation are intentionally skipped because
  the existing authorization covered only the earlier tool-protocol benchmark.

## Autonomous implementation resolutions

- The user's instruction to decide questions without pausing was applied only
  inside the approved v0.9.5 scope; it was not treated as permission to consume
  GPU or cloud quota.
- Global image limits are stricter than or equal to every current adapter limit.
  A model can further reduce the allowed count, bytes, or MIME types through
  its capability contract.
- A provider response that contains a non-HTTPS citation fails the request with
  `invalid-citation`; the Host does not silently omit the unsafe source because
  that would conceal a provider-contract violation.
- Groq Compound is blocked while Web is off because its documented system may
  invoke search as part of the model behavior. This preserves the explicit Web
  enablement requirement.
- Search cancellation records a metadata-only cancellation event before the
  linked request is abandoned. Invalid search contracts and unsafe citations
  record typed metadata-only failures.
- The test suite found and fixed two Gemini stream defects during implementation:
  nullable grounding metadata was read as an object, and a final accepted event
  could skip citations. Both paths now have deterministic regression coverage.
