# v0.9.9 implementation decisions

## Recovery boundaries

- Maintainer diagnostics remain under `tools/diagnostics/` and are outside the
  Web project. Default execution reads metadata and writes only sanitized
  ignored reports; build, E2E, publish, and support-package work are opt-in.
- Full backup stores only Agentic Router data categories and never reads files
  from trusted user workspaces.
- Settings, workspaces, model organization, pricing catalog, optional sessions,
  and optional immutable usage events are normalized into the archive. Key,
  secret, approval, process, and rollback properties are removed recursively.
- Summaries and bounded execution reviews require independent options. Active
  runtime authority is never portable.
- Restore confines manifest paths below the application data root, verifies
  size and SHA-256, creates a pre-restore archive, replaces selected files
  atomically, and restores captured originals after a write failure.
- Missing/zero schema versions migrate sequentially to version 1. Future
  versions or unreadable JSON fail closed, preserve the source, record failure,
  and activate safe mode.
- Safe mode is restart-scoped and has no in-process exit. It never silently
  repairs or deletes data.

## Verification boundaries

- Deterministic fake-provider E2E remains the automated provider boundary.
- No real Ollama or cloud smoke was run because each run requires the user's
  explicit permission.
- Publish verification is a separate PowerShell gate because maintainer tooling
  must never become application runtime code.
