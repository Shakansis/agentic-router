# v0.9.10 implementation decisions

## Context authority

- The Host owns role defaults, request-fit calculation, exact
  provider/model/digest overrides, and the final `num_ctx` sent to native
  Ollama `/api/chat`.
- The global provider context and model-declared context are ceilings. Request
  growth uses only the persisted discrete ladder.
- The coordinator model, not the classification router, is resident. Its
  default target is 8,192 tokens and readiness requires matching
  `context_length` in `/api/ps`.
- A model shared by multiple configured roles remains supported, but the UI
  warns that one Ollama runner may adopt the largest active context.

## Memory evidence

- Analyze is metadata-only and verifies that `/api/ps` did not change.
- Measure accepts one bounded ladder value per explicit request. It refuses to
  run without permission or while another model request is active, verifies
  actual context, and restores the previous target/resident state.
- Measured records are local hardware evidence stored atomically under
  `data/runtime-profiles/ollama-model-memory.json`. They become stale after a
  digest, Ollama version, hardware, context, or relevant runtime-signature
  change.
- Portable YAML carries role policy, memory headroom, and exact overrides, but
  never measured hardware records.
- Parallel runners, flash attention, and KV-cache type remain `unknown` because
  the application does not have authoritative metadata and must not mutate
  global Ollama behavior.

## Permission and validation

- Fake-provider E2E may exercise the entire measurement lifecycle without
  using Rodrigo's GPU.
- Any real Ollama model load, generation, benchmark, smoke, or measurement
  still requires Rodrigo's explicit permission immediately before that run.
- The pre-existing GIF assets remain intentionally untracked and outside the
  v0.9.10 commit.
