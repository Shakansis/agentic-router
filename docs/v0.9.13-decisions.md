# v0.9.13 decisions: traceable execution resilience

## Canonical correlation

The canonical incident lookup key is the ASP.NET Core
`HttpContext.TraceIdentifier`. It is created at the HTTP boundary and propagated
through the scoped Host execution. Request, conversation, turn,
execution-session, provider-attempt, plan-step, and action identifiers are
linked evidence; none replaces another authority.

Every trace event receives a request-scoped monotonic sequence. File append
order is not an execution authority; readers sort the exact trace by sequence.

## Data classification

The incident journal permits only versioned operational fields: identifiers,
timestamp and sequence, stable event/code/stage/status, provider/model and
coordination path, tool name/action identity, retry count, completion/review
state, token arithmetic, and a bounded Host-authored summary selected by event
type.

It has no field for prompts, model responses, hidden instructions, source/file
contents, diffs, raw tool arguments, raw tool/process output, provider bodies,
secrets, credentials, stack traces, or arbitrary paths. Browser and maintainer
views deserialize this same sanitized contract and never read other files.

## Storage and retention

Incident JSONL lives under `data/incidents`, is ignored by Git, excluded by the
existing `data/**` publish rule, and is not part of backups or portable YAML.
Defaults are 14 days, 8 MiB per file, 64 MiB total, and 500 events per trace.
Files rotate by UTC date and size. Lookup is exact and bounded; malformed lines
are counted and skipped without discarding earlier valid evidence.

## Context budgeting and compaction

Native coordinator input is estimated with the same conservative estimator
used by the Ollama adapter. The estimate includes the exact planner system
message, coordinator messages, and serialized tool definitions. The available
input budget is the resolved role maximum context minus reserved output.

When over budget, compaction preserves application-owned project context, the
current objective, latest specialist guidance, a bounded Host summary of plan,
actions and file identities/hashes/sizes, the current correction/recovery
message, and the latest complete assistant/tool pair. Older model-authored tool
history is removed as complete units. A required item that still does not fit
returns `context-item-too-large`; it is never silently truncated into a
different action.

A provider-side `request-context-does-not-fit` permits one retry only when the
new estimate is materially smaller. Exhaustion causes an approved coordinator
path change, or a `partial-context-exhausted` terminal result when completed
work can be reviewed. Resident context and memory defaults do not grow.

## Decisions made autonomously

- Sanitized diagnostic GET remains available in safe mode because the current
  middleware permits read-only API inspection and the endpoint cannot mutate or
  select arbitrary files.
- The browser receives a disabled details action when terminal journal flush is
  not confirmed; copying the canonical trace remains available.
- Schema v2 usage is emitted when a canonical HTTP trace exists. Schema v1
  remains accepted for maintenance/model operations outside an HTTP chat turn.
