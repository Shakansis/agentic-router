# v0.9.6 implementation decisions

This log records decisions made autonomously while implementing v0.9.6. It is
not a roadmap and does not authorize work beyond this release.

## Provider health authority

- Runtime request observations and explicit connection/model-refresh tests are
  the only positive health evidence. A configured key alone yields
  `unknown` or `not-configured`, never `healthy`.
- Recent health uses a bounded in-memory window of 20 outcomes or one hour.
  Health becomes stale after 15 minutes by default; the API accepts a bounded
  override so deterministic tests can prove freshness behavior.
- Browser diagnostics store categories and decisions, not exception messages,
  request bodies, credentials, prompts, responses, images, or model guidance.

## Retry discipline

- Cloud requests use at most three real attempts and eight seconds of total
  retry time. Retry is limited to timeout/network, HTTP 408/429, and retryable
  5xx failures. A streamed request is never replayed after content was emitted.
- Valid `Retry-After` is preferred over exponential delay and is rejected when
  it would exceed the total retry budget. A small jitter prevents synchronized
  retries. Cancellation interrupts both a request and a pending delay.
- Each adapter attempt receives its own usage event. The mandatory local
  fallback remains a separate, later Host strategy and retains its prior rules.

## Usage validation and reconciliation

- Stored events carry `valid`, `valid-with-warning`, or `estimated`; rejected
  inputs never enter the normal append path. Existing/corrupt JSONL input is
  independently validated when queried, aggregated, or reconciled.
- Reconciliation preserves every JSONL byte and atomically replaces only
  `data/usage-aggregates/aggregate-v1.json`. It streams files line by line and
  bounds duplicate detection to immutable event IDs retained for the run.
- A missing or invalid aggregate is rebuilt once during startup. A valid
  aggregate is not rebuilt automatically.

## Validation boundary

- The release gate uses deterministic fake Ollama/cloud providers only. No real
  model, GPU, or cloud quota is required for the implemented contracts.
