# v0.9.11 implementation decisions

## Scope

v0.9.11 is a corrective UX release. It keeps the existing plain HTML, CSS, and
JavaScript architecture and adds no Node, npm, bundler, or frontend framework.

## Dialog authority

All confirmations and text-input requests use one application-owned modal.
Browser-native `alert`, `confirm`, and `prompt` calls are prohibited so every
flow has consistent styling, focus behavior, persistent footer controls, and a
maximum height of 95% of the viewport with internal scrolling.

Errors use top-center, dismissible toasts with a 30-second timeout. Settings
validation also marks the exact control and its intention card where applicable.

## Git configuration boundary

Repository fields remain read-only until the user selects Edit. Identity writes
remain repository-local. The only newly permitted remote mutation is the exact
`origin` address, in Execute mode, after an action-specific preview and explicit
confirmation. The Host accepts HTTPS, SSH URI, or SSH scp-style addresses,
rejects embedded credentials, generates the action ID, and invokes only
structured `git remote add origin` or `git remote set-url origin` arguments.

Changing modes never initializes a repository. From Chat, the Git panel closes,
Execute becomes active, and the user must reopen the panel and separately approve
initialization.

## Provider presentation

Observed health and configuration are rendered in the same provider accordion.
Open state is application state and survives rerendering after Save, Test, or
Refresh. Local Ollama appears as a health-only provider card; cloud providers add
key and billing controls in the same body. No background provider call was added.

## Icons

The Web and Image controls use inline SVG paths from Microsoft Fluent UI System
Icons. Inline SVG avoids a runtime dependency, package manager, or network call,
while accessible names remain available to assistive technology.

Source: https://github.com/microsoft/fluentui-system-icons

## Verification policy

The release is verified with the deterministic fake Ollama/cloud/browser E2E
environment. Real-model benchmarks remain permission-gated because they may use
the user's GPU and are not required to validate these UX-only paths.
