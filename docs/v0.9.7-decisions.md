# v0.9.7 implementation decisions

This log records decisions made autonomously while implementing v0.9.7. It is
not a roadmap and does not authorize work beyond this release.

## Identity and capability authority

- Presentation metadata is keyed by provider plus exact model ID. The alias is
  the primary human label, but qualified IDs remain visible and are the only
  values written into settings or sent to providers.
- Favorites sort first within their provider group, followed by alias or exact
  ID and then exact ID as a deterministic tie-breaker.
- Ollama Local capabilities are inspected through the provider capability
  contract backed by `/api/show`; provider metadata remains authoritative for
  cloud models. An inspection failure leaves capabilities unknown rather than
  inferring them from a model name.
- Conformance is approved only when the cached model ID, digest, Ollama or
  adapter version, and benchmark schema identity still match.

## Profiles and scope

- The configurable profile maximum defaults to 20 and is validated between 1
  and 50. Profiles are global definitions; workspaces persist only a preferred
  profile ID.
- Applying a profile writes every intention's primary and fallback together
  with router, coordinator, comparison model, and optional usage window in one
  settings replacement. It requires confirmation and never invokes inference.
- A cloud primary is invalid unless its fallback resolves to an available
  Ollama Local model. Unavailable required models are rejected during save and
  again during preview/apply.
- The browser's current model lock is intentionally outside profile state, so
  applying a profile affects new requests without rewriting active conversation
  state.

## Persistence and export boundary

- `data/model-organization.json` is a bounded, schema-versioned, atomically
  replaced local file. Portable YAML deliberately excludes aliases, favorites,
  hidden state, notes, profiles, workspace references, secrets, and
  conversations.
- The full local backup archive belongs to the explicit v0.9.9 recovery scope.
  v0.9.7 makes model organization a self-contained persisted category so that
  the later archive can include aliases and favorites without weakening the
  portable YAML contract or introducing a partial backup format early.

## Validation boundary

- The release gate uses deterministic fake Ollama and cloud providers. No real
  local model, GPU, network provider, or cloud quota is required for these
  contracts.
