## CHANGE_GROUP_2_V0.9.12

### Coordination arbitration

- Execute evaluates the selected target before resident eligibility.
- Resolution order is approved target `native-strict`, approved target `structured-action`, eligible resident `native-strict` or `native-adaptive` bridge, then a typed blocked result.
- A resident failure cannot block an independently conformant target.
- Late takeover revalidates resident conformance and memory eligibility at takeover time.

### Conformance profiles

- Added independent `native-strict`, `native-adaptive`, `structured-action`, `guidance-only`, `failed`, and `unknown` states.
- Evidence identity includes provider, exact model, revision/digest, adapter version, runtime/Ollama version, benchmark contract, and profile.
- Structured evidence is cache-only during Execute and must come from an explicit benchmark request; Execute never launches an implicit structured benchmark.
- `native-adaptive` uses a non-executing correction probe: an empty required
  `content` remains rejected, precise Host feedback is supplied, and the model
  must return one corrected call with the exact expected arguments.
- Added deterministic exact-identity invalidation coverage.

### Adaptive recovery

- Deterministic native protocol syntax failures disable that path for the turn instead of repeating the same request.
- Semantic proposal failures receive at most one precise Host-authored correction with tool, rejected contract, reason, and expected shape.
- Repeated semantic failure is fingerprinted and changes strategy without a third repair.
- Coordinator takeover compaction treats semantic-correction messages as control state, preserving the original user objective.

### Structured specialist path

- The specialist proposes exactly one title, tool, and JSON arguments object at a time.
- The Host creates the visible plan, generates stable IDs, validates and approves the action, executes it, and returns the authoritative result before requesting another action.
- The guidance schema no longer asks the model to generate plan/action IDs.

### Tooling normalization addendum

- Added one centralized closed tool-name resolver shared by native tool calls,
  structured specialist guidance, and defensive ordinary action validation.
- The canonical and alias registries use `StringComparer.OrdinalIgnoreCase`.
  Casing-only variants normalize deterministically to the registered identifier.
- Implemented the complete approved initial registry for planning, inspection,
  file mutation, process, validation, read-only Git, and privileged Git tools.
- Resolution occurs before ordinary proposal validation but after the current
  phase supplies its offered canonical names. An alias therefore cannot bypass
  the plan-first state machine.
- Activity reports `original -> canonical` and the resolution source. Execution
  review evidence stores the original name, canonical name, source, final
  validation outcome, and timestamp.
- The resolver changes only tool names. It never renames arguments or weakens
  path, policy, approval, stale-write, process, or Git-write validation.
- Ambiguous names including `get_file`, `open_file`, `edit_file`, `modify_file`,
  `patch_file`, `run_command`, `shell`, `validate`, `commit`, `push`, and `tag`
  remain deliberately unregistered.
- Added a read-only `api/capabilities/tool-names` view so deterministic E2E can
  verify the complete registry and collision-free invariant without executing
  privileged tools.

### Resident memory and lifecycle

- Added `ResidentCoordinationEligibilityService` to combine conformance, requested/actual context readiness, configured RAM/VRAM headroom, observed metrics, target metadata size, locality, and coexistence.
- Metadata-only target allocation remains visibly labelled as an estimate.
- Local direct coordination can use bounded resident eviction, verified absence, and restoration through the existing lifecycle service.

### Browser/activity behavior

- Execution and review surfaces distinguish selected target, effective coordinator, configured resident, execution path, conformance identity, and handoff reason.
- Session activity adds memory-eligibility and path-resolution evidence.
- Pending process and Git stage/unstage approvals expose an editable
  terminal-styled argument surface. Accepted edits remain the same canonical
  tool/action, are revalidated by the Host, and are reflected in the card.
- Approval, execution, and result now remain in one activity card. Decision
  controls disappear after the decision; the authoritative output is retained
  in an initially collapsed `Execução` section.

### Automated evidence

- Added fake models for successful and failed structured-action paths.
- Added fake Groq native tool planning for target-first cloud arbitration without real quota use.
- Added coverage for target-first coordination, independent structured evidence, one semantic repair, repeated failure, exhausted paths, exact runtime identity invalidation, Host-owned IDs, resident recovery, cancellation, and restoration.
- The fake server now records unexpected handler exceptions and aborts the request, preventing silent test hangs.
- Added focused coverage for the complete alias registry, canonical names,
  ordinal case-insensitive lookup, collision freedom, unknown names, phase

### Limitations

- Real Ollama and real cloud validation were intentionally not run without fresh permission.

- The Host remains the sole authority for plan identity, registered tools, arguments, workspace confinement, approvals, execution, retries, recovery, cancellation, persistence, and terminal state.
- Invalid structured proposals are never executed.
- Unsupported image input is rejected before provider transmission; images are not silently stripped.
- Cloud benchmarks still require explicit external-provider permission.
- Git remote mutation rejects credentials and remains separately previewed and approved.

  cross-session or post-decision revisions are rejected.
