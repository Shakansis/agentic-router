# Model library

Settings > Models and routing > Model library groups installation, filters and per-model preferences. Existing automatic routing, model profiles, favorites, hidden models, aliases, notes and GPU affinity are preserved.

- Browse Ollama opens https://ollama.com/search in a separate tab.
- Install model accepts an exact library name (including namespace and tag). A missing tag means `latest`. Downloads start only on an explicit button/Enter action. The existing Ollama streaming pull path reports provider progress. The original onboarding endpoint continues to restrict downloads to its recommendation set.
- Remove from Ollama asks for confirmation of the exact model. The Host invokes the installed `ollama rm <model>` with separate arguments, no shell, and `OLLAMA_HOST` set to the configured server. Removal waits for active AR inference through the existing request tracker. Success requires a zero exit code and absence from the subsequent installed-model listing. Only then does AR delete that model's context/performance overrides, GPU affinity and presentation preferences (alias, favorite, hidden flag and note). Saved model profiles referencing it are deleted and affected workspace profile preferences are cleared. Cleanup can also be retried when the model is already absent. A CLI failure or unverified removal does not delete configuration. Shared blobs are managed by Ollama.
- Saving Settings repairs old orphaned overrides and affinities after successful discovery confirms that their model names are absent from the same configured Ollama endpoint. Previously saved runtime overrides for an obsolete digest are also removed when the tag now identifies a different installed revision; that installed tag's other preferences and profiles are retained. A newly submitted incorrect digest remains a validation error. An unavailable server, cloud-only discovery fallback, or a change of Ollama endpoint never serves as deletion evidence. An unknown digest is not evidence of an obsolete revision. The repair is persisted only after the entire Settings draft passes validation. Browser drafts for a model removed through AR are also discarded so they cannot recreate its configuration.
- Removal does not choose another model for routing. Existing route references remain visible for explicit replacement. Conversations and usage evidence remain historical records.
- Both model operations honor the existing safe-mode mutation restriction. Same-model operations cannot overlap. Failure is visible and retryable; a successful CLI exit with an unchanged registry is reported as unverified, never as removed.
- Last used in AR is the latest successful, nonempty inference event for the exact provider/model in retained usage history, including Chat, Execute and model tests. Dates use the browser's locale/time zone. It is not the Ollama file modification date. No recorded use does not mean never used: usage outside AR and expired/purged history are unavailable. No additional persistence or telemetry is introduced.
- Alias/note save with their card action; favorites and hiding save on click. GPU affinity keeps the existing settings footer save behavior. Installation/removal refresh model availability without replacing the user's unsaved settings form.

The library uses the existing settings controls and confirmation modal, with persistent field labels, explicit hints, status feedback, responsive cards, and a single surrounding settings scroll area.

Validation uses browser + Host + an external fake Ollama HTTP/CLI boundary. No user-owned model is downloaded or removed by automated tests.

Settings validation presents a keyboard-accessible error summary. Each error selects the affected section, model/revision or inference profile, opens its details, and scrolls directly to the highlighted input with an associated inline message. Navigation preserves unsaved drafts. The context editor identifies inherited role defaults separately from a model-specific override.

The 2026-10-29 regression passed 41 browser/API E2Es covering the model library, settings error navigation, atomic validation, runtime performance and cloud fallback. It includes failed/unverified removal, profile cleanup (including comparison models), workspace preferences, offline discovery, endpoint changes, obsolete versus newly incorrect digests, and installed models excluded from routing. Release build completed with zero warnings/errors; scoped formatting, JavaScript syntax and intended-diff checks passed.
