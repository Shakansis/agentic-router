# v0.9.14 manual acceptance and known limitations

This record keeps real-use acceptance separate from deterministic automated
coverage. Passing Host, fake-provider, or browser tests is necessary, but it is
not sufficient to declare model-driven Execute behavior production-ready.

## Current assessment

- File creation is acceptable.
- File editing is poor and remains unaccepted as reliable.
- File deletion is unacceptable and is reported as not working in real use.

The v0.9.14 corrective implementation strengthens Host effect verification,
approval argument handling, deletion rollback, conversation UI behavior, and
Undo workspace resolution. It does not reclassify the editing or deletion
experience as accepted.

## Required follow-up

Run a real-model Execute benchmark that separately measures create, edit, and
delete outcomes, including disk verification and undo. This benchmark may use
local Ollama models only after the user explicitly confirms that the GPU is
available; no real-model inference is part of the v0.9.14 closure tests.
